# 账号、渠道与调度优先级

适用版本：**1.0.7**。

## 设置优先级

在面板 **账号池与运维** 选择国内或国际区域。在账号行的“调度优先级”输入非负整数，点击“保存优先级”。

| 状态 | 含义 |
| --- | --- |
| 名称旁“优先级 100” | 当前已保存的值 |
| 未保存 | 输入框中存在草稿，调度继续使用已保存值 |
| 保存中 | 正在提交到服务端 |
| 已保存 · 重启保留 | 服务端已写入账号 JSON |
| 保存失败提示 | 保留草稿，可再次点击保存 |

默认优先级为 `100`，取值范围 `0–2147483647`，数字越小越早调用。保存成功后账号表按启用状态、优先级排序。定时刷新保留未提交草稿；账号名称旁的徽章始终显示已保存值。

## 持久化

优先级保存为账号 JSON 的 `priority` 字段。API 响应、账号导出包含该字段；重启重新载入。旧账号缺少该字段时默认 `100`。

凭证刷新保留优先级。重新 OAuth 登录或覆盖导入同一账号时，若新的凭据没有提供 `priority`，保留原值；若导入内容明确提供合法优先级，使用该值。保存失败会恢复原调度值。

Docker 部署需要持续挂载 `/app/accounts`。更换挂载目录会加载另一套账号和设置；部署步骤见[部署说明](integration-plan.md)。

## 调度顺序

1. 请求根据 Key 绑定或默认出口选择国内／国际账号池。
2. 账号池从最小优先级开始，结合停用、冷却、在途限制、模型限制、保留积分和每日限额判断候选账号。
3. 该优先级没有可用账号时，尝试下一个优先级。
4. 同优先级内，免费模型按所属区域公平轮询；付费模型继续采用所配置的公平／权重／积分地板选号规则。

例如 A、B 的优先级为 `10`，C 为 `100`：先在 A、B 中按原策略选取；两者都不可用时再使用 C。若 A 为 `0`，它可用时会比 B、C 更早选取。长期只使用最小优先级是该设置的预期效果。

付费模型会话可以继续复用绑定账号；出现更小优先级的可用账号时重新选择。免费模型沿用按区域公平轮询，不以会话绑定固定占用单个账号。国内与国际池分别判断，账号优先级无法跨 Key 的固定渠道。

## 管理 API

修改账号的入口为 `POST /accounts/set`，需要面板会话及原有管理鉴权。请求示例：

```json
{"uid": "account-uid", "priority": 10}
```

成功返回 `{"account": {..., "priority": 10}}`。非法值返回 `400`；账号不存在返回 `404`。该入口也保留 `enabled`、`proxy` 和 `proxySlot` 的独立更新功能。客户端余额与用量查询使用 API Key，见 [API 说明](api.md)。
