# 账号、渠道与公平调度

适用版本：**1.1.0**。

## 优先级

在控制台 **账号池** 中选择国内或国际区域，输入非负整数并点击“保存优先级”。默认 `100`，范围 `0–2147483647`，数字越小越早调用。

| 状态 | 含义 |
| --- | --- |
| 名称旁优先级徽章 | 已保存并用于调度的值 |
| 未保存 | 本地草稿，调度继续使用原值 |
| 保存中 | 正在提交 |
| 已保存 · 重启保留 | 已写入 SQLite 并导出账号 JSON |

SSE 刷新保留草稿和输入焦点；离开输入后更新列表。凭据刷新保留优先级；重新登录／覆盖导入未明确提供 `priority` 时保留原值。旧账号缺少字段时使用 `100`，保存失败保留草稿及原调度值。

## 调度顺序

1. 按 API Key 的固定渠道或默认出口选择国内／国际池。
2. 从最小优先级开始，过滤停用、冷却、在途上限、模型限制、保留积分和每日限额。
3. 当前优先级无可用账号时尝试下一优先级。
4. 同优先级内比较实际消费加在途预估；选号与预估登记在同一个原子操作内完成。

例如 A、B 优先级 `10`，C 为 `100`：先均衡 A、B，两者都不可用时再使用 C。公平调度不会越过仍有可用账号的更小优先级，也不会跨渠道调用。

## 免费与付费均衡

| 类型 | 主要比较值 | 相同时 |
| --- | --- | --- |
| 免费模型 | 当天全部免费模型实际 `total_tokens` ＋在途免费 Token 预估 | 在途请求较少优先，然后轮询 |
| 付费模型 | 当天实际积分消耗＋在途付费积分预估 | 剩余积分／闲置补偿加权；关闭加权时轮询 |

免费模型合并计量，不按单个模型分开。例如 A 已完成 20K、B 已完成 50K，但 A 在途预估 40K，会优先选有效负载较小的 B。不同请求长度及预估误差仍会造成短期差距，后续实际结算继续校正。

输入预估按请求中的文字与工具定义估算；预期输出使用该渠道与模型近期用量的移动平均，初次默认 512 Token，并受请求的输出上限约束。付费预估优先使用账号与模型近期确认的每 Token 积分消耗，并按本次 Token 预估缩放；否则使用渠道／模型样本，未知时预留 1 积分。预估只用于选取账号，不是账单、额度扣款或真实 Token 统计。

请求完成后先持久化实际用量，再原子移除该请求预估。打开上游失败、切换账号、异常或关闭响应都会清理对应预估；跨本地零点的在途请求仍保留预估，结束时归入结束当天。

免费请求默认跳过会话粘性。付费绑定只有在账号仍是同优先级内有效积分消耗最少的可用账号时复用；否则重新分配。`pool.free_fair_pick` 默认开启，关闭后免费请求沿用原有选号及会话规则。

## 取消与未知用量

客户端取消请求时，已经收到的上游 Token／积分会计入每日调度及用量总计；取消记录单独分类，不增加完成次数、失败率或有效生成速度样本。上游失败已有确认消费也保留。

取消前没有收到 usage 时，记录 `usage_missing`，不把在途预估当作消费。实际账号余额可能包含上游未报告的消耗，这部分无法从取消流中准确追回。重启恢复的是已持久化实际用量，运行中预估由活跃请求持有。

免费／付费分类优先使用实际积分：已确认零积分为免费，正积分为付费；缺少积分字段时参考渠道模型目录。记录保留 `billing_mode`，不会虚构未报告的积分。

## 控制台与持久化

每日计量按服务本地零点重置，重启从 SQLite 恢复。每日限额为 `0` 时仍持续计量；在途估算参与公平选号，限额判断继续依据实际用量。

账号视图包含 `freeTokensToday`、`dailyCreditsToday`、`pendingFreeTokens`、`pendingCredits`。控制台显示当天实际消费与在途预估，Token 自动使用 `K/M/B`，API 和导出保留原始数值。

账号 JSON 的 `priority` 字段继续导出，SQLite 保存账号、设置、Key 和会话绑定。Docker 必须持续挂载 `/app/accounts` 与 `/app/usage`；备份方法见[部署说明](integration-plan.md#sqlite-迁移与备份)。

## 管理 API

`POST /accounts/set` 使用面板会话及管理鉴权：

```json
{"uid":"account-uid","priority":10}
```

成功返回 `{"account":{...,"priority":10}}`，非法值为 `400`，不存在的账号为 `404`。`enabled`、`proxy` 和 `proxySlot` 仍可分别修改。客户端余额与用量查询使用网关 API Key，见[API 说明](api.md)。
